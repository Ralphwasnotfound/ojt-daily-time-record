## Architecture and boundary

The immutable original private selfie plus finalized database metadata produce a
dynamic branded Admin presentation. No second image is uploaded, no original is
overwritten, and no text is baked onto the only copy. This is the permitted dynamic
watermark architecture, not an exported JPEG/PNG watermark. The official timestamp
is generated by U4.2; capture/browser time is never substituted.

No migration, RPC, bucket, policy, grant, Realtime publication, attendance transaction,
two-session rule, student capture UI, or Activity implementation changed for U4.4.

## Trusted data and presentation

The row provides only student/session lookup IDs and the selected action. The service:

1. Reads the exact `(student_uid, attendance_session_id, action_type)` proof under RLS.
2. Reads trusted identity with bounded `admin_students(target_uid, page_size: 1)`.
3. Reads the associated attendance session under RLS and checks ownership/action,
   official timestamp against the appropriate punch, valid coordinates and accuracy.
4. Calls `admin_attendance_days(target_uid, day_limit: 1, on_day)` for the Manila
   Time In day and uses its U3 ordinal, derived over `(time_in, id)` for the full day.
5. Downloads only that finalized proof's private object with the authenticated
   existing Supabase client. No service-role browser client, signed/public URL, or
   mutation is introduced.

The dialog displays the unchanged BSIT logo, Torres Capitol College, OJT Monitoring
& DTR, crimson/gold branding, trusted name/Student ID, TIME IN/OUT, Session 1/2,
official date/time in Asia/Manila (including seconds), coordinates to five decimal
places, rounded meter accuracy, and a private evidence indicator. The selfie uses
`object-contain` and stays visible above the metadata panel. Internal UUIDs, paths,
request/reservation IDs and raw API errors are not rendered. No reverse geocoding,
address invention, map, analytics, geofence, facial recognition or liveness check.

Identity is the current trusted profile, not a newly invented immutable historical
name snapshot. Coordinates are recorded browser location evidence; neither they
nor the selfie/watermark independently prove physical presence. The database is
authoritative, not a screenshot of the presentation.

## Private access and lifecycle

Approved Admin authorization is checked locally and enforced by existing database
and Storage RLS. Students gain no new route or cross-student access. Reads are lazy:
attendance history itself never eagerly fetches proofs or full images.

An authenticated Blob becomes a temporary object URL after allowed MIME/size checks.
The browser image decoder reports malformed images. Close, Escape, unmount,
account/role change, selected student/session/action change and retry abort old
requests, clear metadata and revoke the URL. Generation and identity checks discard
late responses. A 20-second deadline bounds metadata/download loading; Close stays
available throughout. The native modal provides focus containment and a close target;
body scroll is restored on teardown. Errors remain friendly and retryable without
logging private metadata. Historical proof absence is neutral:

> No attendance proof is available for this historical record.

The viewer does not provide permanent download/export or derived-image persistence.
After bytes have been legitimately downloaded, RLS cannot revoke screenshots or
copies already made by a user. Local auth-state changes clear the on-screen copy.

### Student behavior and security

One bounded query obtains only session/action existence flags for the currently
loaded attendance page. View Proof appears only for confirmed attached proofs.
Historical proofless actions omit the button. Availability errors hide unconfirmed
controls while preserving readable attendance; Refresh attendance retries.

No private image, coordinates or detailed proof metadata is prefetched. Opening a
proof uses trusted finalized metadata and authenticated private Storage retrieval.
Student identity checks require the current approved student to match the requested
owner; database and Storage RLS independently enforce ownership even when client
checks are bypassed. The reader provides no mutation/public URL path.

Shared cleanup now explicitly includes route and audience changes as well as close,
account/student/session/action changes and unmount. Switching proofs discards the
previous metadata and revokes its object URL before another image is shown.
